# 保护层、故障行为与验收

以下为本机 2026-09-05 文件核对结果，不是本次抓包或断网实测结论。先识别版本，不能混用旧模板的功能描述。

| 层 | 实际作用 | 不能据此保证 |
| --- | --- | --- |
| CLI wrapper | 启动前检查、会话绑定、代理变量、Seatbelt、TTY 清理 | 绕过 wrapper 的原生 CLI 自动受保护 |
| UserPromptSubmit / PostToolBatch | CHECK 失败阻止相应 Hook 阶段 | 登录、遥测、更新、流式连接等每条请求均被检查 |
| HTTP gate | 默认代理经专用入站转发 | 解密 HTTPS、逐请求重检、失效即断开全部连接 |
| Mihomo 专用入站 | 与普通规则入口分离、绑定出口 | 同名节点背后服务器未变、地区绝对可信 |
| macOS Seatbelt | 约束该进程及继承限制的子进程出站 | 允许的本地服务不会代转外网、其他独立进程也受限 |
| 浏览器监控 | 周期验证，失败关闭专用 context | 零延迟、逐包验证、与 CLI 动态 IP 行为完全一致 |
| 工具信息 Hook | 匹配工具调用的文本规则 | 拦截原生 os.*、系统调用或所有子进程的信息访问 |

## 本机 CLI 检查时序

1. --fast 检查 rule、TUN、IPv6、端口、绑定路由和叶子，不访问外部探测。alive=false 不单独拒绝，它可能只是测速结果。
2. 绑定会话需要新出口探测；普通 CHECK 可复用 90 秒成功缓存。
3. 完整探测依次尝试三个 trace（各最多 7 秒），再做 API 根路径诊断。403/404 等状态不能证明登录成功或账号异常。
4. 探测不可用且符合既有绑定条件时，旧成功结果可能宽限至 180 秒；明确非 TW 则拒绝。不能无限续期或把超时当成功。
5. 同叶子的 TW 新 IP 可更新会话，不因动态 IP 本身杀 CLI。CHECK 失败阻止相应操作，保留会话供重试。

Hook 35 秒、控制口调用约 32 秒。总预算还须计入排队/控制器耗时，并发互斥可能误拦截。控制口超时后不能再同步追加一次 32 秒探测。网络 Hook 不读取或回显 prompt，不输出凭证。

## 实现边界，不能省略

- 现用 gate 的转发连接函数不调用检查函数；CHECK 是独立控制操作，没有失效后关闭全部隧道的持续监控。因此“全进程每条请求先检查”“波动立即杀进程”目前不成立。
- 沙箱允许 localhost:* 和若干 Unix socket，另一允许的本地代理/服务可成为旁路。NO_PROXY 有本地开发例外，不是 gate 全覆盖的证明。
- 缓存未按所有路由配置完整分区；共享 /tmp/claude-network-guard.session.json 会被多个 CLI 会话覆盖或解除绑定，不能声称多会话隔离完善。
- gate 对一个既有内部开发域名走普通规则入口，其他目标走专用入口。迁移须重新授权例外，不复制内部域名或扩大为全量 DIRECT。
- trace/GeoIP 是外部观测信号，不是全部服务请求的路径证明。

更强的全流量 fail-closed 是独立改造：收窄网络出口、防本地转发旁路、新连接验证、失效关闭存量隧道、按会话与路由分区缓存。仍需处理持久连接和检查竞态，不能只加 prompt Hook 就宣称完成。

## IPv6 与 DNS

- 分别核对 macOS 活跃网络服务/路由、Mihomo IPv6/DNS/TUN、浏览器 DoH/WebRTC。Mihomo ipv6:false 不等于整个系统已关闭 IPv6。
- DHCP DNS 列表不是泄漏直接证据；TUN 是否接管需路径证据，退出后可能回退 DHCP。不能凭开关保证无泄漏。
- 获准 DIRECT 的国内服务使用国内解析器是分流预期；Claude 域名与浏览器旁路需另测。
- 不为修 Claude 清空全局 DNS、改所有网卡或删系统配置。记录旧值、限定改动、提供恢复方式。
- 不把第三方“纯净度/信任分”当账号安全保证。
