# 保护层、故障行为与验收

先区分目标机器的实际部署与仓库内的通用模板。不能把模板能力直接写成某台机器已经部署，也不能把旧部署边界套到新模板。

| 层 | 实际作用 | 不能据此保证 |
| --- | --- | --- |
| CLI wrapper | 启动前检查、会话绑定、代理变量、Seatbelt、TTY 清理 | 绕过 wrapper 的原生 CLI 自动受保护 |
| UserPromptSubmit / PostToolBatch | CHECK 失败阻止相应 Hook 阶段 | 登录、遥测、更新、流式连接等每条请求均被检查 |
| HTTP gate | 默认代理经专用入站转发；新版主备模板持续探测并在切换/失效时关闭其管理的活动隧道 | 解密 HTTPS、证明所有绕过 gate 的流量、替代 TUN/规则核验 |
| Mihomo 专用入站 | 与普通规则入口分离、绑定出口 | 同名节点背后服务器未变、地区绝对可信 |
| macOS Seatbelt | 禁止改 Mihomo 控制口。Shell/脚本/数据库走真实网络 | 子进程直连 Anthropic、IPv6 旁路；依赖 HTTP_PROXY + Clash 规则 + TUN |
| 浏览器监控 | 周期验证，失败关闭专用 context | 零延迟、逐包验证、与 CLI 动态 IP 行为完全一致 |
| 工具信息 Hook | 匹配工具调用的文本规则 | 拦截原生 os.*、系统调用或所有子进程的信息访问 |

## 典型 CLI 检查时序

1. --fast 检查 rule、TUN、IPv6、端口、绑定路由和叶子，不访问外部探测。alive=false 不单独拒绝，它可能只是测速结果。
2. 绑定会话需要新出口探测；普通 CHECK 可复用 90 秒成功缓存。
3. 完整探测依次尝试三个 trace（各最多 7 秒），再做 API 根路径诊断。403/404 等状态不能证明登录成功或账号异常。
4. 探测不可用且符合既有绑定条件时，旧成功结果可能宽限至 180 秒；明确非 TW 则拒绝。不能无限续期或把超时当成功。
5. 同叶子的 TW 新 IP 可更新会话，不因动态 IP 本身杀 CLI。CHECK 失败阻止相应操作，保留会话供重试。

Hook 35 秒、控制口调用约 32 秒。总预算还须计入排队/控制器耗时，并发互斥可能误拦截。控制口超时后不能再同步追加一次 32 秒探测。网络 Hook 不读取或回显 prompt，不输出凭证。

## 实现边界，不能省略

- 先识别部署版本。旧 `~/.local/claude-guard/` gate 的转发连接与 CHECK 是独立机制，可能没有持续监控或失效后关闭全部隧道。新版 `~/.claude-guard/` 主备模板会周期性新鲜探测当前生效角色，并在切换或健康失效时关闭它自己管理的活动隧道；切到备用后，备用成为被持续探测的当前角色。它仍不等于逐包验证，也不会关闭绕过 gate 的连接。
- 沙箱放行普通出站后，shell/远端库不再因 EPERM 失败。Claude/Anthropic 仍靠 HTTP_PROXY → gate → 专用入站。未走 HTTP_PROXY 的客户端若直连 Anthropic，依赖 Clash TUN + claude 规则集；TUN 关闭时可能泄漏。
- 缓存未按所有路由配置完整分区；共享 /tmp/claude-network-guard.session.json 会被多个 CLI 会话覆盖或解除绑定，不能声称多会话隔离完善。
- HTTP CONNECT 默认真 Claude 走专用入站。仅用户授权的域名后缀可走规则入站。不要复制另一台机器的域名，也不要把数据库流量送进专用入站。
- trace/GeoIP 是外部观测信号，不是全部服务请求的路径证明。

更强的全流量 fail-closed 仍是独立改造：收窄网络出口、防本地转发旁路、覆盖所有新连接、按会话与路由分区缓存。新版主备模板已加入切换屏障、活动隧道关闭与状态原子写入，但保护范围仍限于该 gate 管理的连接，不能据此宣称系统级零旁路。

## 可选主备状态机

1. 默认不开启主备，行为保持单节点兼容。
2. 开启时只接受固定 `primary_node`、`secondary_node` 与一个恰好只直接包含这两个叶子的 Selector `ai_group`；任一时刻 `expected_node` 只有一个值。失败阈值限制为 2-5，严格探测间隔限制为 5-60 秒。
3. 已有新鲜严格验证时，单次有界的控制口超时、trace 超时或 Anthropic 临时不可达只保留上一条已验证路由并立即复核；连续失败达阈值才关门。叶子漂移、地区不符、TUN/IPv6 或主备状态不一致是明确不安全证据，首次即关门。
4. 主节点连续新鲜探测失败达到阈值后，写入 `switching=true`，正常 CHECK 与新连接立即拒绝，并关闭活动隧道。
5. 控制器切到备用后，必须重新解析真实叶子并完成明确地区与 Anthropic 响应探测。只有成功才原子提交 `active_role=secondary`、更新 `expected_node` 并清除 switching。
6. 备用验证失败则切回主节点并读回确认，再对主节点执行一次无缓存、严格地区与 Anthropic 探测。只有全部成功才解除 switching；Selector 写入失败、读回不符或严格复验失败都会写入 `blocked`，继续 fail closed。
7. 备用运行中的临时可达性失败也只容忍到同一连续阈值；到阈值后阻断但不自动回切。回切可能造成再次漂移，必须由用户明确操作并重新验证。
8. `blocked`、已有 `switching`、角色/`expected_node` 不一致或 Selector 实际叶子并非主节点时，故障转移入口也拒绝重入；Selector 切到备用后必须先读回真实叶子，再进入严格探测。

## IPv6 与 DNS

- 分别核对 macOS 活跃网络服务/路由、Mihomo IPv6/DNS/TUN、浏览器 DoH/WebRTC。Mihomo ipv6:false 不等于整个系统已关闭 IPv6。
- DHCP DNS 列表不是泄漏直接证据；TUN 是否接管需路径证据，退出后可能回退 DHCP。不能凭开关保证无泄漏。
- 获准 DIRECT 的国内服务使用国内解析器是分流预期；Claude 域名与浏览器旁路需另测。
- 不为修 Claude 清空全局 DNS、改所有网卡或删系统配置。记录旧值、限定改动、提供恢复方式。
- 不把第三方“纯净度/信任分”当账号安全保证。
